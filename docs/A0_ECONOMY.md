# SwarmBrain/A0 Economy

## Purpose

SwarmBrain uses two deliberately separate value layers:

1. **ACC** — internal, non-transferable-off-network accounting units for verified useful work.
2. **USDC** — external settlement value recorded only after a successful x402 settlement.

Neither avoided cost nor ACC is represented as cash.

## ACC issuance

ACC can be issued only by a `verified_work` ledger event.

A verified-work event must contain:

- a task ID;
- one or more unique contributors and positive aggregate contribution weight;
- receipt/evidence supporting the completed work;
- reference cost and actual cost;
- an explicit ACC issuance amount.

The ledger deterministically allocates integer ACC microunits across contributors. Rounding remainder is assigned deterministically.

## ACC transfers

Agents may transfer existing ACC balances to other agents for internal services.

Transfers:

- require positive existing balance;
- cannot overdraw;
- cannot mint new ACC;
- conserve total issued ACC;
- remain in the tamper-evident hash chain.

This supports internal microtransactions for routing, verification, retrieval, correction, memory reuse, and other swarm work without pretending ACC is USD.

## Avoided cost

`reference_cost - actual_cost` is stored as avoided cost.

Avoided cost measures economic efficiency. It is **not** treasury cash and does not increase USDC balance.

## External revenue

Real external revenue enters the ledger only through `usdc_settlement`.

A USDC settlement requires:

- positive amount;
- network;
- unique transaction identifier;
- task ID;
- evidence from the payment settlement path.

Duplicate transaction identifiers are rejected.

## x402 merchant flow

The merchant implementation follows the x402 v2 authorization flow:

1. return a payment requirement if no payment signature is supplied;
2. ask the configured facilitator to verify the signed payment;
3. execute the requested resource only after verification succeeds;
4. ask the facilitator to settle after successful resource execution;
5. record USDC revenue only when settlement reports success;
6. return the payment response header and resource result.

The repository does not contain a wallet private key.

## First merchant product

`swarmbrain/merchant_server.py` exposes:

- `GET /health` — unpaid health information;
- `POST /v1/route` — paid, read-only swarm route selection.

The route service does not dispatch work to peers. It only returns ranked routes from existing swarm state.

The merchant server is disabled by default and binds to localhost by default.

Required live configuration:

- `A0_MERCHANT_ENABLED=1`
- `A0_MERCHANT_PUBLIC_URL`
- `A0_PAY_TO` — public payout address only
- `A0_USDC_ASSET`
- `A0_FACILITATOR_URL`

Optional:

- `A0_ROUTE_PRICE_ATOMIC` (default 10000 atomic USDC units)
- `A0_PAYMENT_NETWORK` (default `eip155:8453`)
- `A0_MERCHANT_HOST` (default `127.0.0.1`)
- `A0_MERCHANT_PORT` (default `8787`)

Facilitator authentication, when required, must be supplied through deployment secret configuration and never committed to this repository.

## Autonomous GitHub ingress

Trusted issue comments beginning exactly with:

`SwarmBrain job: `

are parsed as bounded JSON jobs.

The GitHub Actions bridge:

1. validates the commenter allowlist and job prefix;
2. runs the finite SwarmBrain job;
3. writes runtime and economic receipts;
4. commits the permitted state artifacts;
5. posts the persisted result back to the originating issue.

Replies generated by the automation do not use the job prefix, preventing self-trigger loops.

## Accounting invariants

- ACC is internal accounting, not a redeemable dollar promise.
- Only verified work issues ACC.
- ACC transfers conserve total ACC supply.
- Avoided cost is not cash.
- Quotes and payment verification are not revenue.
- Only successful x402 settlement creates a USDC revenue event.
- One on-chain settlement transaction can be recorded only once.
- Private signing keys are never required by the swarm merchant code.
